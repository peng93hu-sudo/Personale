# 红军反查机制（RED TEAM PROTOCOL）

> 红军（Red Team / RT）是整套系统的**信用阀门**。
> 原则一句话：**写结论的人不核结论；核结论的人默认怀疑、独立找源、证据不足即降级。**
> 触发：**两条产线的每一次更新都必须过红军**（这是"每次更新都需要红军反查"的硬实现）。
> 版本：v1.0 · 2026-06-28

---

## 1. 为什么必须有红军

调研/业务 Agent 有"完成任务"的内在动机，容易：把单一来源当共识、把预测当事实、把厂商 PR 当中立、把"找到了"当"核实了"。红军的存在就是**和这些动机对冲**——它的成功定义是"挑出问题"，不是"通过结论"。

## 2. 红军的独立性规则（不可放松）

1. **来源独立**：红军**不得复用**被核查者引用的来源做自证，必须自己重新检索第二来源。
2. **默认怀疑**：证据不足时，判 `unverifiable` 或 `partially_supported`，**不准默认通过**。
3. **不受 PM 指挥放松**：PM 可以要求红军复核，但不能要求红军"放水"。
4. **降级不删除**：被证伪/无法核实的结论**保留并标注**，让决策人看到"曾信过什么、为何改"。

## 3. 判定标准（verdict 四档）

| verdict | 含义 | 触发条件 | 报告标签 |
|---|---|---|---|
| `confirmed` | 已证实 | ≥2 个独立权威源一致，数字口径吻合 | ✅ 绿 |
| `partially_supported` | 部分支持 | 方向对但数字/范围有出入，或仅 1 源 | 🟡 黄 |
| `refuted` | 已证伪 | 找到可靠反证，原结论错误 | ❌ 红 |
| `unverifiable` | 无法核实 | 找不到独立源 / 来源失效 / 口径不明 | ⚪ 灰 |

> 默认门槛：`min_independent_sources_for_confirmed = 2`（你可调）。

## 4. 红军作业清单（每条 finding 必跑）

```
[ ] 1. 来源真伪：source_url 能打开吗?是该机构原文还是转述?
[ ] 2. 时效：source_date 是否过期?有没有更新版本推翻它?
[ ] 3. 数字核对：key_value 与原文一致吗?口径(年份/单位/范围)对吗?
[ ] 4. 独立第二源：自己检索,是否有独立来源印证或反驳?
[ ] 5. 夸大检测：是否把"规划/预测/个案"说成"已落地/共识/普遍"?
[ ] 6. 给 verdict + evidence_url + corrected_value
```

## 5. 输出格式（VERDICT_SCHEMA）

```json
{
  "dimension": "中国-政策与监管",
  "redteam_summary": "整体可信,但2项把征求意见稿当已落地,已降级",
  "verdicts": [
    {
      "claim": "被核查结论",
      "verdict": "confirmed | partially_supported | refuted | unverifiable",
      "evidence_note": "核查理由",
      "evidence_url": "红军独立找到的佐证/反证",
      "corrected_value": "修正值或 N/A"
    }
  ]
}
```

## 6. 整体可信度信号（给决策人）

每次刷新后统计红军判定分布：

```
红军判定汇总: { confirmed: X, partially_supported: Y, refuted: Z, unverifiable: W }
可信度 = confirmed / (总数)        # 越高越稳
风险面 = (refuted + unverifiable) / 总数   # 越高越要警惕
```

> 这个分布直接上**控制塔 index.html** 顶部，作为整份研究的"信用评分"。

## 7. 业务线的合规红线（红军额外盯）

红军在业务线还要查**合规**，红线（默认，你可加）：
- ⛔ 不设计需要牌照而未取得的售电/金融/融资租赁结构。
- ⛔ 不虚构客户/供应商/承诺。
- ⛔ 不规避电网接入/备案等强制流程。
- ⛔ 跨境（意大利）涉及 GSE/Terna 接入与税务激励，必须按官方流程，不臆造可得性。

## 8. 红军与决策人的关系

- 红军**给判定，不替你拍板**。当出现"A 源说 X、B 源说 Y"的分歧，红军把分歧摆清，**由你裁决采信谁**，裁决记入 CHANGELOG。
- 红军判定 `refuted` 的结论若你仍想采用，需你**显式 override** 并留记录（系统保留你的最终决策权）。
