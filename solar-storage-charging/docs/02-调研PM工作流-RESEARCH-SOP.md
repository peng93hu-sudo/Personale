# 调研 PM 工作流 SOP（RESEARCH-SOP）

> 负责人：**PM-R 调研 PM**。执行：R1/R2/R3 × {中国, 意大利}。质控：RT 红军。
> 目标：把"光储充在中国/意大利"的不确定信息，压成**可查、可验证、可追溯**的研究结论。
> 节奏：**每周刷新 1 次**（可手动加刷）。版本：v1.0 · 2026-06-28

---

## 1. 核心逻辑（你点名要看的）

```
核心逻辑：多源交叉 + 红军反查 → 把"听说"压成"可信"
要点：政策（能不能做）· 经济性（划不划算）· 格局（谁在做、怎么赚）
分析结果：每维度一份带来源+置信度+红军判定的结论集
分析流程：拆维度 → 并行调研 → 红军逐条反查 → 汇总+缺口 → 你调参 → 出报告
```

## 3. 标准作业步骤

**Step 1 · PM-R 拆题派工**
- 按上表给每个维度生成调研指令（含：核心问题、必查来源类型、时间窗、地域、强制输出 schema）。
- 设定参数（见 §5），写入派工单。

**Step 2 · 并行调研（R1/R2/R3）**
- 每个维度 Agent **必须**：① 用 WebSearch 多关键词检索；② 用 WebFetch 打开权威原文核对；③ 按 `FINDINGS_SCHEMA` 输出，每条带 source_url + date + confidence。
- 优先级来源：官方（发改委/能源局/GSE/ARERA/Terna/EU）＞ 行业协会/权威数据（CNESA/BNEF/IEA/Motus-E/ANIE）＞ 主流财经媒体 ＞ 公司公告（打折）＞ 自媒体（仅做线索）。

**Step 3 · 红军逐条反查（RT）**
- 红军拿到调研结论 JSON，**不复用其来源**，独立找第二来源。
- 对每条 finding 判 `confirmed / partially_supported / refuted / unverifiable`，给 evidence_url 与 corrected_value。详见 `04-红军反查机制`。

**Step 4 · 汇总 + 缺口清单**
- PM-R 合并 6 维度结论 + 红军判定，生成：
  - **核心结论**（按要点：政策/经济性/格局，中×意对照）
  - **红军判定分布**（✅/🟡/❌/⚪ 计数 = 整体可信度信号）
  - **缺口清单 open_questions**（下周或业务线要补的）

**Step 5 · 你审阅 + 调参**
- 你看汇总，可：改参数、加题、裁决分歧。指令记入 CHANGELOG。

**Step 6 · 出报告（PUB）**
- 更新 `research/光储充-调研报告.md`（带版本块 + diff）。
- 更新 `research/sources.md` 来源登记。
- 渲染 `html/research.html`（内置打印为 PDF）。

## 4. 每个流程 Agent 的"核心要点 + 考虑的参数"（决策人视角）

| Agent | 核心要点 | 考虑的参数（旋钮） | 红军重点盯 |
|---|---|---|---|
| R1 政策 | 落地 vs 规划、文号真伪、国家 vs 地方 | 时间窗、地域、政策层级 | 文号是否存在、是否过期 |
| R2 经济性 | 数字口径、预测 vs 实际、可交叉验证 | 省份、储能时长、电价情景、成本年份 | 数字是否被夸大、口径混用 |
| R3 格局 | 事实 vs PR、收益机制讲清、含失败案例 | 玩家清单、模式优先级、案例颗粒度 | 是否轻信厂商宣传 |

## 5. 参数手册（你可调）

```yaml
research_params:
  time_window: "2024-2026"        # 研究时间窗
  geo_weight: { china: 0.5, italy: 0.5 }   # 中意权重
  storage_duration_h: [2, 4]      # 储能时长情景
  confidence_gate: "medium"       # 进报告的最低置信度
  redteam_strictness: "high"      # 红军怀疑强度
  min_independent_sources_for_confirmed: 2
  weekly_refresh: true            # 周刷开关
  extra_topics: []                # PM 本周新增主题（如 "意大利MACSE容量拍卖细则"）
```

## 6. 周度"是否新增内容"的判断（PM-R 职责）

每周刷新时，PM-R 回答三问，结果记入 CHANGELOG：
1. **有没有新政策/新机制**值得设为新维度？（如新一轮容量电价、新补贴）
2. **上周缺口**哪些已可补全、哪些升级为正式维度？
3. **业务线反喂**的缺口是否纳入？（如"CER 分成细节"）

## 7. 验收标准（PM-R 对成果物）
- [ ] 每条结论有 source_url + date + confidence。
- [ ] 每条结论有红军 verdict。
- [ ] 关键数字至少 2 个独立源或标注 single-source。
- [ ] 缺口清单非空（永远有"还不知道的"）。
- [ ] 报告有版本块 + 本次 diff。
