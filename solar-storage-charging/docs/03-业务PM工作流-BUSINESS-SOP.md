# 业务 PM 工作流 SOP（BUSINESS-SOP）

> 负责人：**PM-B 业务 PM**。执行：B1 货源 → B2 客户 → B3 成交结构 → B4 财务测算。质控：RT 红军。
> 目标：把调研结论变成"**找到货 → 找到客户 → 设计中间流程 → 算得过账**"的成交闭环。
> 节奏：**每天产出 1 个成果物 + 1 个可执行动作**。版本：v1.0 · 2026-06-28

---

## 1. 核心逻辑（你点名要看的）

```
核心逻辑：用调研结论选定"最优商业模式假设",再在源端找货、需求端找客户、中间设计成交结构并算账
要点：源头结果（有什么货/服务）· 成交方（谁买谁卖）· 商业模式（中间怎么赚）
源头结果：货源清单(品类/价格/账期/资质)
分析结果：成交方案(交易结构 + 分成 + IRR + 风险)
分析流程：选模式 → 找货(B1) → 找客户(B2) → 设计流程(B3) → 测算(B4) → 红军反查 → 你调参 → 出业务HTML
```

> **成果物即产品本身**：业务线的交付不是"分析报告"，而是**可以拿去执行的成交方案**（货从哪来、卖给谁、中间怎么分钱、能赚多少）。

## 3. 标准作业步骤（成交闭环）

**Step 0 · PM-B 选模式**：读调研结论 → 选 1-2 个假设 → 设参数（§6）。

**Step 1 · B1 找货（源头侧）**
- 在源端定位可获取的产品/货物/服务，记录：品类、单价区间、账期、资质、交期、MOQ、来源。
- 输出**货源清单**（每项可追溯）。

**Step 2 · B2 找客户（需求侧）**
- 定位真实买方画像 + 需求规模 + 付费意愿 + 决策链 + 触达路径。
- 输出**客户画像与需求规模**（区分"目标画像"与"已确认线索"）。

**Step 3 · B3 设计中间流程（成交结构）**
- 设计交易/分成/合同结构：谁出钱、谁运营、谁分钱、合同形态、利润点、风险分配。
- 输出**交易结构图 + 分成方案 + 风险分配表**。

**Step 4 · B4 财务测算**
- 单项目模型：投资、收入（套利/服务费/补贴）、IRR、回收期、敏感性（电价/利用率/补贴）。
- 输出**财务模型 + IRR/回收期 + 乐观/基准/悲观**。

**Step 5 · 红军反查（RT）**
- 反查：数字是否成立、货源/客户是否真实可追溯、结构是否合规（合规红线见 `04`）。
- 判 verdict，降级不合格项。

**Step 6 · 你审阅 + 调参 + 出 HTML**
- 你选采信、调参、批准对外动作。
- 更新 `business/商业模式与交易设计.md` + 渲染 `html/business.html`，记 CHANGELOG。

## 4. 每个流程 Agent 的"核心要点 + 考虑的参数"（决策人视角）

| Agent | 核心要点 | 考虑的参数（旋钮） | 红军重点盯 |
|---|---|---|---|
| B1 货源 | 真实可获取、价格有据、资质齐 | 品类、地域、单价区间、MOQ、交期 | 供应商/价格是否编造 |
| B2 客户 | 画像可触达、规模有量级依据 | 客户类型、规模门槛、决策链、地域 | 是否虚构具体客户 |
| B3 成交结构 | 闭环、利润点清晰、风险有归属 | 模式、分成比例、风险分配、合同期 | 是否设计灰色结构 |
| B4 财务 | 假设显性、敏感性完整 | 投资、电价、利用率、补贴、折现率 | 是否只报乐观情景 |

## 5. "成果物即产品"的每日交付定义

每天必须落一个**看得见、能执行**的东西，至少满足其一：
- 一份更新的货源清单（新增/更新 ≥1 个可追溯货源）；
- 一份更新的客户画像或触达路径；
- 一版更新的成交结构或分成方案；
- 一次财务模型更新（参数/敏感性）；
- **+ 1 个明确的"下一步可执行动作"**（如"联系 X 类供应商询 Y 规格报价"）。

## 7. 闭环：业务反喂调研
业务线跑的过程中产生的"数据缺口/新机会"，由 PM-B 汇总 → 反喂 PM-R，进入下周研究判断（如"需要意大利 CER 分成的官方比例"）。这保证两条线咬合，而不是各跑各的。

## 8. 验收标准（PM-B 对成果物）
- [ ] 货源/客户**可追溯**（来源、价格、规模有依据）。
- [ ] 成交结构闭环、利润点与风险都讲清。
- [ ] 财务模型假设显性 + 有敏感性。
- [ ] 每条更新过红军 verdict。
- [ ] 当日有 1 个可执行动作。
