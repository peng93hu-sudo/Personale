# 充电桩 调研 × 业务 多智能体系统

> 国内为主、意大利(欧盟)为参照 · 多智能体交付 · 信息可查可验证可追溯
> 项目PM:Claude Code 编排 · 最终决策人:你

本仓库用**多智能体(Multi-Agent)**方式,为充电桩(EV Charging)行业持续产出**可决策、可追溯**的调研与业务成果。

## 两条线 + 红军

- **调研PM线(每周刷新)**:7 个维度研究 Agent 并行 → 红军逐维度反查 → 综合成决策结论。
- **业务PM线(每天产出)**:依据调研,制定机制 → 找源/找客户 → 模拟最优商业模式 → 设计流程 → 产出成果物(成果物=产品本身)。
- **红军(Red Team)**:贯穿两线,**每次更新都反查**,逐条核对来源、识别夸大/过时/幻觉,给裁决与置信度。

## 本轮成果(2026-06-28)

- **调研线**:15 Agent · 748K tokens · 7 维度 · **113 来源** · 红军核验 133 条(✅78/🟡43/⚠️8/❌4)。
- **业务线**:6 Agent · 5 候选商业模式打分 · 推荐"模式B" · **业务红军裁决 no-go**(8 条压力测试 / 2 致命),并给出整改前提 —— 这正是"投钱前先证伪"的价值。
- **复现**:`python3 scripts/gen_report.py && python3 scripts/gen_business.py && python3 scripts/gen_html.py`

## 三可标准(硬约束)

**可查**(每个数字挂 URL+出版方+日期)· **可验证**(红军实际打开来源核对)· **可追溯**(结论→数字→来源→红军裁决 全链路入库)。无来源不进报告。

## 节奏

- 调研:**每周**一次(PM 判断是否纳入新政策/新玩家/新模式)。
- 业务:**每天**一个成果物。
- 红军:**每次更新都跑**。

## 如何调参引导结果

1. 编辑 `workflows/research.workflow.js` 的 `DIMENSIONS`(增删维度)。
2. 调整地域权重 / 时间窗 / 红军严格度(`effort`)。
3. 给业务线设硬约束(回收期、毛利、可成交周期)。
4. 重跑:`Workflow({scriptPath: "workflows/research.workflow.js"})`。

详见 `docs/01-多智能体体系设计.md`。
