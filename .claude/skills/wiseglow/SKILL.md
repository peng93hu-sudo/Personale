# WiseGlow 代码修改 Skill

## 一句话

用户说「加 / 改 / 删 WiseGlow 的 xxx」→ 按项目现有约定产出**一个 .py 文件**,并告诉他放哪、怎么接入。

**不做**:跑模拟分析、生成报告、Lark 集成。

## 项目位置

`~/Desktop/wiseglow_v2_full/`

## 能改什么(对照触发词)

| 类型 | 例子 | 触发词 |
| --- | --- | --- |
| 资产 Asset | BESS、光伏、充电桩 | 加资产、改 BESS、改光伏、改充电桩 |
| 收入流 Revenue | PPA | 加收入流、改 PPA |
| 模块 Module | 计算 / 数据模块 | 加模块、改模块 |
| 算法 Algorithm | 调度 / 优化算法 | 改算法 |
| UI 主题 Theme | 配色 / 样式 | 改 UI、改主题 |

## 工作流(每次都走这 6 步)

1. **判定类型 + 动作**
   先确定是「加 / 改 / 删」,以及对象属于上表哪一类。不清楚就先问一句,别猜。

2. **找参考实现(先读后写,关键步骤)**
   在项目里打开一个同类的现有 .py 当模板:资产就找现成的 BESS / 光伏文件,收入流就找现成的 PPA 文件,其余类推。
   照搬它的类结构、基类 / 接口、命名风格、参数与单位约定。**不要凭空发明结构。**

3. **收集参数**
   按对象类型列一个最小参数清单让用户确认(如名称、容量 / 功率、成本、效率、约束等)。缺哪个补哪个。

4. **产出一个 .py 文件**
   - 一次只产出一个文件,聚焦单一对象。
   - 结构、命名、import 风格与第 2 步的参考实现保持一致。
   - 只写「定义」本身,不写跑模拟 / 画图 / 报告的代码。
   - 顶部一行注释说明这是什么。

5. **给接入说明**
   明确告诉用户:
   - 文件放哪个目录、叫什么名字。
   - 要不要在某个注册表 / `__init__` / 配置里登记;若要,给出具体那一行怎么加。
   - 有没有需要同步改的地方(如 UI 下拉、默认参数表)。

6. **自检清单(交付前过一遍)**
   - [ ] 类型 / 动作判定正确
   - [ ] 结构与同类实现一致
   - [ ] 参数齐全、单位标注清楚
   - [ ] 给了明确的放置路径 + 接入步骤
   - [ ] 没有越界做模拟 / 报告 / Lark

## 改 / 删 怎么做

- **改**:先定位现有文件,只动需要改的字段 / 方法,产出修改后的完整文件或精确 diff,并说明影响面。
- **删**:指出要删的文件 + 所有引用它的地方(注册表、配置、UI),让用户清楚连带要清理什么。

## 交付格式

1. 一句话说明做了什么。
2. 完整 .py 文件内容(代码块)。
3. 「放哪 + 怎么接入」的步骤。
4. 需要用户决定 / 确认的点(如果有)。

## 明确不做

- 不跑模拟、不做结果分析。
- 不生成报告 / 图表。
- 不碰 Lark 集成。
